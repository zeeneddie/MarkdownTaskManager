Beslissing 1: Epic Structuur

Vraag: Eén Epic of Meerdere Epics?

Optie Voordelen Nadelen
A: Eén Epic Eenvoudiger beheer, duidelijke scope, één eigenaar Groot (215 files)
B: Meerdere Epics Parallelle ontwikkeling, fijnere granulariteit Overhead, onderlinge afhankelijkheden

✓ KEUZE: Optie A - Eén Epic

Reden: De 8 entiteiten zijn sterk gekoppeld. AfspraakClient en AfspraakHulpverlener kunnen niet zonder Afspraak bestaan. Splitsen in features biedt voldoende granulariteit.

Deze keuze zorgt voor één verantwoordelijke Product Owner, voorkomt cross-epic dependencies, en maakt release planning eenvoudiger.

Vraag: Welke Features identificeren we?

Conclusie: Afspraak is een Hub Module

Afspraak wordt door 20+ andere modules aangeroepen. Dit betekent:

  • Wijzigingen aan Afspraak hebben hoge impact
  • Backward compatibility is cruciaal
  • API-first benadering aanbevolen (facade pattern)
  • Extensive regression testing nodig bij elke wijziging
Dit verklaart waarom de huidige code zo stabiel is gehouden - elke wijziging raakt facturatie, NZa-rapportage en het cliëntportaal.
